# HOME AI Bridge — установка в Proxmox VE одной командой

Этот **публичный** репозиторий содержит установщик HOME AI Bridge для Proxmox VE и распространяет проверенный Linux AMD64 бинарный пакет. Основной репозиторий исходников `DeadSoulf/home-ai-bridge` остаётся **приватным**.

## Установка без GitHub-токенов

В **Shell хоста Proxmox VE от root**:

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/DeadSoulf/home-ai-bridge-installer/main/install.sh)"
```

Установка больше **не запрашивает GitHub Personal Access Token, пароль GitHub или какие-либо ключи**. Пакет скачивается из публичного GitHub Release, контрольная сумма SHA-256 закреплена в установщике. Внутренние ключи для аутентификации самого HOME AI Bridge генерируются автоматически внутри LXC и не выводятся на экран.

Во время работы установщик спрашивает CTID, хранилище диска и шаблонов, сетевой мост и IPv4 (DHCP по умолчанию). Ввод `yes` перед созданием нового контейнера обязателен.

Создаётся отдельный **unprivileged Debian 13 LXC**, 1 CPU, 512 MiB RAM, 4 GiB диск; сервер запускается как systemd-служба под непривилегированным пользователем.

## Доступ по сети

Сервер **слушает все IPv4-интерфейсы контейнера**: `0.0.0.0:8787`. Он не ограничен `127.0.0.1`.

Для безопасности входящие запросы принимаются с частных IPv4-адресов (RFC 1918), а вызовы MCP и запросы агентов требуют внутренней авторизации. Сам факт прослушивания всех интерфейсов не означает разрешения анонимного управления устройствами. Не публикуйте порт в Интернет и настройте правила Proxmox Firewall.

На ранее установленном сервере Windows ничего не меняется. Агентов переключают на новый LXC только после проверки.

## Проверка

Замените `106` на созданный CTID:

```bash
pct exec 106 -- systemctl status home-ai-bridge --no-pager
pct exec 106 -- curl -fsS http://127.0.0.1:8787/health
pct exec 106 -- hostname -I
```

В браузере или по curl можно проверить `http://АДРЕС_LXC:8787/health` из локальной сети, если Proxmox Firewall разрешает соединение.

## Безопасность и исходники

[Просмотрите install.sh](https://github.com/DeadSoulf/home-ai-bridge-installer/blob/main/install.sh) перед его запуском от root. Использование формата команды похоже на Proxmox Community Scripts, но это самостоятельный установщик, не связанный с их проектом.

**Обратите внимание:** бинарный пакет публичен, приватный репозиторий — нет. Токены агентов не входят в пакет. Не размещайте конфигурационный файл из работающей инсталляции в публичном репозитории.

## Установка в существующий LXC

Теперь стандартная однострочная команда сначала предлагает **режим 1 (создать LXC) или режим 2 (установить в существующий Debian 13 LXC)**. Это отдельные действия: создание контейнера выполняет Proxmox, установка HOME AI Bridge — наш скрипт. Режим 2 не вызывает `pct create`, не меняет диски и не пересоздаёт существующие контейнеры.

Если на Proxmox ошибка `lxc-usernsexec ... tar ... Permission denied` сохраняется даже после смены хранилища, создание Debian 13 LXC можно попробовать отдельно через Proxmox Community Scripts:

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/community-scripts/ProxmoxVE/main/ct/debian.sh)"
```

Это **сторонний скрипт**, ознакомьтесь с его содержимым перед запуском от root. В расширенных настройках выберите непривилегированный Debian 13, желаемый CTID (например 106), диск, vmbr0 и DHCP. Сам по себе этот способ не гарантирует исправления прав Proxmox: Community Scripts также опирается на `pct create` и может встретить ту же ошибку.

**После успешного создания Debian 13 LXC** (контейнер должен быть запущен) используйте прежнюю однострочную команду HOME AI Bridge и выберите **2**, затем CTID. Или выполните прямую команду:

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/DeadSoulf/home-ai-bridge-installer/main/install-existing.sh)"
```

Установщик проверяет статус LXC, Debian 13, архитектуру x86_64 и флаг unprivileged; он не будет перезаписывать уже установленный HOME AI Bridge. Скачивает тот же публичный бинарный релиз с закреплённой контрольной суммой SHA-256, копирует бинарный сервер и systemd unit и запускает только службу внутри контейнера. GitHub-токен не нужен.

**Важно:** команда `post-pdm-install.sh` из первоначального примера настраивает Proxmox Datacenter Manager после установки; она не создаёт LXC. Для создания Debian LXC пример Community Scripts — `ct/debian.sh`.
